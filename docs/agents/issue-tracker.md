# Issue tracker: GitHub

Issues and specifications live in GitHub Issues for `akbarsahata/alumni-platform`. Use the GitHub plugin for reading, searching, publishing, updating, labeling, and closing issues. Pass the explicit repository identity in tool calls.

## Conventions

- Search existing issues before publishing to avoid duplicates.
- When a skill says publish to the issue tracker, create a GitHub issue containing the complete specification or task body.
- When fetching a ticket, read the issue body, labels, and relevant comments.
- Apply the state label mapped in triage-labels.md; preserve unrelated labels when updating state.
- If a required plugin operation is unavailable, report the limitation before using a different tracker workflow.
- For wayfinding, use native sub-issues and dependencies when available. Otherwise link children through a parent task list and record explicit blocker references in each child.
