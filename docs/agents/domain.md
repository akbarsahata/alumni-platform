# Domain docs

This is a single-context repository: glossary terms live in GLOSSARY.md at the repository root, and architectural decisions live in docs/adr/.

Before exploring the codebase, read GLOSSARY.md when present and the ADRs relevant to the area being changed. If either is absent, proceed silently; create domain documents lazily when terms or decisions are resolved through domain modeling.

Use glossary vocabulary in specifications, issues, test names, and design discussions. Surface conflicts with accepted ADRs explicitly before proposing changes.
